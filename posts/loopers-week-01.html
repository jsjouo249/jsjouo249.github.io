LOOPERS · WEEK 01

루퍼스 1주차 기록

모호한 요구를 질문과 규칙으로 바꾼 과정을 자신의 언어로 설명합니다.

TAGS

#loopers #weekly #learning

이번 주에 한 일

기준 문장 한 줄만 보고, 구현을 위해

  • 사실과 질문
  • 여섯 규칙과 반례
  • 외부 계약과 내부 경계

를 확인하여, 구현하기 전 문서를 구성한다.

사실과 질문

사실

  • 기준 문장에서 확인 된 사실 2개를 적는다.

질문

  • 사실이 아닌 제품 담당자에게 확인이 필요한 질문 3~5개를 적는다.

여섯 규칙을 반례와 연결한다

  • 문서에 있는 INV-001 ~ INV-006까지의 규칙과 해당하는 반례를 작성

외부 계약과 내부 경계

  • 외부 API 계약을 어떻게 노출하고, 내부에서 어떻게 책임을 나눌지에 대한 구현 원칙 작성

어려웠던 점

보통 현업에서는 단일 문장이 아닌 기획서나 회의를 진행하며, 필요한 정책들을 같이 정의하기도 하는데, 이번엔 한 문장에 대해서 스스로 고민하고 정리하는 과제였습니다.

기획서를 읽고, 회의를 통해 불변식과 반례, 예외 케이스들을 정리하는 것도 쉽지 않다고 생각되는데, 단일 문장만으로 정리를 하다보니, 여태 했던 프로젝트나 범용적으로 알고 있는 배경지식들을 자연스레 떠올리게 되어, 생각이 계속 꼬리에 꼬리를 물어 너무 커진 것 같다고 생각했습니다.

범용적으로 하는 것이 가장 좋으나, 멘토링을 통해 아직 구현하지 않아도 되는 건 구현 하지 않는 게 좋다는 말씀을 들었고, 스스로 YAGNI를 떠올리면서 필요한 것과 범용적이라 해도 당장은 필요없는 기능들을 하나씩 제거해나갔습니다.

가장 필요한 기능만 있으니, 너무 단순해 진게 아닐까 싶지만 b2b 개발을 하면서, 당연한게 당연한 것이 아니게 되고, 필요치 않아 보였지만 필요한게 되는 걸 보면서 지금 당장 필요하다고 생각되는게 나만의 생각이라는 생각을 항상 가지고 있어서, 정리하는 것에 도움이 된 것 같습니다.

이번주는 선택과 집중 및 YAGNI에 대해 한번 더 생각해 볼 수 있었던 과제인 것 같습니다.
